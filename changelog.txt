** Hellotext for WooCommerce Changelog **

2026-11-07 - version 2.0.2

* Run on PHP 7.4 again: 2.0.0 failed to load there.
* Declare the supported WordPress, WooCommerce and PHP versions, and compatibility with High-Performance Order Storage.
* Log failed Hellotext requests to the WooCommerce logs (source "hellotext") when WP_DEBUG is on.
* Sanitize the checkout link's products and the Webchat card's source before reading them.
* The release zip is hellotext.zip and installs to the hellotext folder, as the Woo Marketplace requires.

2026-11-06 - version 2.0.1

* Declare WooCommerce as a required plugin: WordPress 6.5 and later only activate Hellotext while WooCommerce is active.

2026-11-06 - version 2.0.0

* Remove the Webchat settings. The Webchat, popups and other widgets are configured in Hellotext.
* Load the latest Hellotext.js from jsDelivr on the storefront only, no longer in wp-admin.
* Report the page section (homepage, product collection, product) on every event, Webchat messages included, and show the Smart Alert section configured for it.
* Ship a Hellotext Push service worker, so visitors can subscribe from the Smart Alert.
* Add the Webchat's product cards to the WooCommerce cart, crediting the addition to their message.
* Track page.viewed, cart.viewed, and checkout.started once per cart.
* Track order.placed for Checkout block, block themes and customers who never return from the payment page, once the order is paid or on hold.
* Never attribute order, refund or new user events to the shop manager's browser session.
* Create and link customer profiles on product views, cart changes and checkout, not only on registration.
* Report cart totals after WooCommerce recalculates them, the quantity removed in cart.removed, and stop reporting purchased items as removed.
* Stop starting a PHP session on every request; the cart snapshot lives in the WooCommerce session.
* Reconnect after deactivation or a credential change, revoke the WooCommerce API key on deactivation, and move the integration when the Business ID changes.
* Keep the working API key until Hellotext accepts a new one. A failed connection shows on the settings page and is retried when the settings are saved again.
* Send the WooCommerce version when connecting, and open Hellotext checkout links (?hellotext_checkout) on stores older than WooCommerce 10.0.
* Open only pages of the store from the Webchat's add to cart, and retry linking a customer's session when Hellotext did not link it.
* Fix profile and session requests losing the /v1 API prefix, coupons with errors being tracked as redeemed, and orders with deleted products failing to track.
* Point the plugin at another Hellotext environment with the HELLOTEXT_API_URL constant instead of APP_ENV.
